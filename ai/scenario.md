# 시나리오: 순찰 중 위험 발견

사용자와 문답으로 정했습니다(2026-11-22). 결정은 그대로 따르고, `[가정]`은 구현하면서 실물로 정합니다.

## 1. 한 줄 요약

로봇이 실내 방(약 5×5 m)을 지도 위 지점대로 **자율 순찰**하다가, 카메라로 **사람**을 보면 멈춰 인사하고,
**쓰러진 사람**을 보면 멈춰 대시보드에 경고하고 사람이 확인할 때까지 그 자리에서 영상을 보냅니다.
사람은 대시보드에서 언제든 조종·정지할 수 있습니다.

## 2. 장비·역할

| 구성 | 역할 |
| --- | --- |
| 로봇 1대 + 비전 모듈 | 이동(공식 API), 영상 전송 |
| 노트북 대시보드 | 감지(사람·쓰러짐), 위치 추정(VSLAM), 경로 판단, 경고 표시, 조종 |
| 라이다(USB) | 표시만 — 순찰·위치에 쓰지 않음([lidar-frozen.md](lidar-frozen.md)) |

판단은 노트북, 동작은 로봇이 합니다. 로봇은 지금처럼 명령이 600 ms 끊기면 스스로 멈춥니다([protocol.md](protocol.md)).
2대(A/B) 협업 역할은 **나중에 정합니다**. 지금은 1대만 설계합니다.

## 3. 상태

```text
대기 ──순찰 시작──▶ 순찰 ──사람 감지──▶ 인사 ──사람 사라짐──▶ 순찰
                    │                                   
                    ├──쓰러진 사람 감지──▶ 경고 대기 ──사람이 '확인'──▶ 순찰
                    ├──조종 키 입력──▶ 수동 ──키 놓고 [가정] 3초──▶ 순찰
                    └──정지/비상 정지──▶ 대기(잠김, 사람이 잠금 해제해야 다시 시작)
```

| 상태 | 로봇 | 대시보드 |
| --- | --- | --- |
| 순찰 | 다음 지점으로 이동 | 지도에 현재 위치·다음 지점 |
| 인사 | 멈춤 → `scrape_a_bow` → `set_default_pose()` | "사람 있음" 표시 |
| 경고 대기 | 멈춤 + 경고 동작([가정] `nodding_motion`) 후 서서 대기, 영상 계속 | 경고 배너·소리, 감지 시각·신뢰도·근거 프레임 번호, **확인** 버튼 |
| 수동 | 키를 누르는 동안만 이동(지금 대시보드 방식) | "수동" 표시 |
| 대기 | 정지·잠김 | 순찰 시작 버튼 |

규칙:

- **수동 개입:** 순찰 중 조종 키를 누르면 자율을 멈추고 수동으로 바뀝니다. 키를 놓고 일정 시간([가정] 3초) 입력이 없으면 순찰을 **자동 재개**합니다(사용자 결정).
- **정지·비상 정지는 자동 재개하지 않습니다.** Space(정지)·Esc(비상 정지)는 수동 키가 아니라 대기로 보내며, 다시 움직이려면 사람이 잠금 해제 후 순찰 시작을 눌러야 합니다.
- **인사 반복 방지:** 같은 사람에게 계속 인사하지 않도록 인사 뒤 [가정] 10초 동안 사람 감지로 다시 인사하지 않습니다. 사람이 앞을 막고 있으면 멈춘 채 기다립니다.
- **쓰러짐 우선:** 사람과 쓰러진 사람이 함께 보이면 쓰러짐을 따릅니다.
- **감지 불확실:** 영상이 끊기거나 오래되면(최신 프레임 [가정] 1초 초과) 순찰을 멈추고 "영상 없음"을 표시합니다. 감지 결과 없음을 "위험 없음"으로 보지 않습니다.
- **위치 잃음:** VSLAM이 위치를 잃으면 멈추고 대시보드에 알립니다. 사람이 수동으로 옮기거나 다시 시작합니다.
- 동작 그룹은 [mechdog-api.md](mechdog-api.md) 목록에서만 고르고, 끝날 때까지 기다린 뒤 `set_default_pose()`로 돌아옵니다.

## 4. 순찰 경로

1. 사람이 수동으로 방을 한 바퀴 돌며 VSLAM 지도를 만듭니다.
2. 대시보드 지도에서 순찰 지점을 클릭해 순서대로 저장합니다.
3. 순찰은 지점을 차례로 돌고 마지막 다음에 처음으로 돌아갑니다.

## 5. 감지

| 대상 | 방법 | 근거로 남길 것 |
| --- | --- | --- |
| 사람 있음 | 노트북에서 사람 검출 모델 | 시각, 신뢰도, 임계값, 프레임 번호 |
| 쓰러진 사람 | 자세 추정으로 몸 기울기·머리 높이 판단, [가정] 연속 N프레임 유지 시 확정 | 같음 + 연속 프레임 수 |

- 쓰러짐 검토에서는 사건당 박스 JPEG 두 장과 시각·판정·메모를 노트북에 보관합니다. 현장 사진은 커밋하지 않습니다.
- 모델은 노트북 CPU에서 돌 수 있는 가벼운 것으로 고르고, 라이선스를 확인합니다.

## 6. 만드는 순서

사람 또는 전방 초음파 감지 시 정지·화면 표시·빨간 LED를 사용합니다. `--greet`는 새로 감지한 사람에게 인사하고 10초간 재인사를 억제합니다. 실제 쓰러짐 감지를 확정하면 인사를 취소하고 30초간 정지합니다. 운영자는 쓰러짐 로그에서 박스 사진 두 장을 검토합니다. 본체 동작은 실물 미검증입니다. [대시보드](dashboard.md)

| 단계 | 내용 | 끝났다고 보는 조건(실물) |
| --- | --- | --- |
| 1 | **카메라 fps 개선** — 비전 모듈 해상도·펌웨어 조정으로 초당 장수 올리기(현재 약 2.2장). VSLAM에 모자라면 다른 방법을 사용자에게 묻기 | 노트북 수신 fps·지연 측정값 기록 |
| 2 | **감지 + 경고 + 반응(수동 조종 상태)** — 사람 감지 시 인사, 쓰러짐 감지 시 정지·경고·확인 버튼 | 조종 중 사람·쓰러진 자세(모형 가능)에서 반응 확인 |
| 3 | **VSLAM 지도** — 비전 모듈 영상으로 지도·위치 추정 | 방 한 바퀴 지도, 같은 지점 재방문 시 위치 오차 기록 |
| 4 | **지점 순찰 + 수동 개입·자동 재개** | 지점 순찰, 감지 시 반응, 개입 후 재개 |
| 5 | 2대(A/B) 협업 | 역할은 나중에 사용자와 정함 |

## 7. 아직 모르는 것

- 비전 모듈로 VSLAM에 충분한 fps·화질이 나오는지(공식 API에 오도메트리가 없어 영상만으로 위치를 추정해야 함).
- 걸을 때 흔들림이 VSLAM·감지에 주는 영향.
- 순찰 이동 명령: 대시보드가 `move(step, angle)` 명령을 계속 보내 지점으로 가는 방식([protocol.md](protocol.md))으로 충분한지.
- `[가정]` 값들(재개 3초, 인사 10초, 영상 1초, 쓰러짐 N프레임).
