# 사용자 통합 확인 순서

에이전트는 아래 업로드·굽기·전원·구동을 실행하지 않았습니다. 한 대상이 정상임을 확인한 뒤 다음 대상으로 넘어갑니다.
대상 ID A/B와 USB 포트, 본체 ESP32와 카메라 ESP32-S3를 먼저 구분합니다. 실패하면 다음 단계로 진행하지 않습니다.

| 순서 | 사용자 작업 | 정상 결과 | 실패 시 확인·복구 |
| --- | --- | --- | --- |
| 0 | PC에서 전체 unittest·합성 전체 데모 실행 | 테스트 통과, simulation=true | 코드 버전·Python 환경. 실물에 연결하지 않음 |
| 1 | 기존 본체 main.py·설정과 카메라 전체 플래시 백업 | A/B별 백업과 해시 보관 | 대상 보드·용량부터 재확인, 백업 없으면 중단 |
| 2 | 카메라 A에 최신 합본, 다음 B | /status ID·센서·PSRAM·실제 JPEG 차원 | 포트·전원·설정 확인, 해당 보드 백업으로 복구 |
| 3 | 두 로봇 카메라 동시 수신·디코딩 측정 | 화질 문서의 숫자 목표 확인 | 낮은 해상도·오래된 프레임·오류는 합격 아님; 모델·프로필 재검토 |
| 4 | 본체 읽기 도구로 API 존재·배터리·IMU 확인 | 단위·반환형·호출 시간 기록 | 오류는 추측하지 않고 [확인 필요]. 후보 보정/서보 API 호출 금지 |
| 5 | 지지 상태에서 본체 A/B용 Python 업로드 | 예외 없음, boot 래치·정지 TEL | 자동 실행 중단 후 기존 main.py·설정 복원 |
| 6 | Pi 고정 위치 점검 어댑터 연결 | A/B 출처 분리, 주/보조 ACK와 역할 표시 | unknown은 준비 아님. RESET·순찰을 누르지 않고 로그 수치 확인 |
| 7 | 고정 위치에서 한 링크 단절·복구 | B 승계는 ACK 후 확인, 복구 A는 자동 이동하지 않음 | 래치·ACK·세대·임대 확인. 주 역할 표시는 구동 허가가 아님 |
| 8 | 부품 도착 후 라이다 USB 단독→별도5V→J5→TCP→/scan | 전압·기동 전류·115200·프레임/Hz 기록 | 극성·공통GND·TX/RX·버퍼·전원부터 확인 |
| 9 | 별도 실물 구동 범위를 정한 후 정지 시험 | ESTOP·600ms 단절·저전압/예외에서 정지 | 즉시 전원 차단 수단 사용, 원인 확인 전 재개 금지 |
| 10 | 실제 모델·지도·위치·보정 확인 후 안내 통합 | 정확도·지연·장애물·관리자 이탈 정지 검증 | 아직 고정 위치 어댑터가 이동을 차단하므로 준비 전 차단을 풀지 않음 |
