# 사용자 실물 테스트

자동 개발 에이전트는 합성 테스트와 코드 검토를 담당합니다. 사용자는 실제 하드웨어 관측과 실행 승인을 담당합니다.
실물 확인 이슈의 체크리스트를 한 항목씩 수행하고 [빈 결과 양식](results-template.md)을 복사해 댓글로 남깁니다.
이 폴더에는 절차와 빈 양식만 저장합니다. 실제 영상·개인정보·자격 정보는 커밋하지 않습니다.

## 먼저 하는 읽기 확인

상세 배선과 단계별 예상 결과는 [bringup.md](../bringup.md)를 따릅니다.

| 순서 | 사용자가 할 일 | 실행 위치 | 결과 |
| --- | --- | --- | --- |
| 1 | 로봇 A/B 표시, 전원 OFF에서 외관·고정·배선 확인 | 실제 장치 | 손상·느슨한 고정 없음 |
| 2 | J5 핀 방향·전압 측정 | 멀티미터 | 기대 전압과 극성 일치 |
| 3 | `b1_board_info.py`를 기존 main.py 교체 없이 실행 | 로봇 메인 보드 REPL | API·UART 지원 OK/FAIL 기록 |
| 4 | 라이다를 빼고 `b2_uart_loopback.py` | 로봇 REPL, J5 루프백 | 256바이트 일치 |
| 5 | 별도 5V·공통 GND를 확인한 뒤 `b3_lidar_info.py` | 로봇 REPL | health·모델·펌웨어, 일련번호는 게시하지 않음 |
| 6 | `b4_wifi_echo.py`, PC의 `rtt_probe.py` | 각각 로봇 REPL / PC | RTT·손실·응답 공백 기록 |
| 7 | `camera_check.py <확인한 URL>` | PC·Pi | 상태·프레임 수, 영상 저장 없음 |

실행 승인에는 **대상 A/B, 스크립트, 읽기 확인 범위**를 명시합니다. 알 수 없는 전압·핀·전원 공급,
발열·냄새·부팅 반복·예상치 못한 움직임이 있으면 즉시 중단하고 전원을 끕니다.
현재 main.py가 움직임을 자동 실행한다면 해당 상태에서 REPL 시험을 시작하지 말고 먼저 백업·실행 중지 방법을 확인합니다.

## 업로드·구동은 별도 승인

읽기 확인이 끝나도 펌웨어 업로드와 이동 시험 승인이 자동으로 생기지 않습니다.
사용자가 기존 main.py와 펌웨어 복구 방법을 확보한 뒤 대상·시험 범위를 명시적으로 승인합니다.
부팅 래치 → HELLO → 상태 수신 → RESET → 짧은 저속 이동 → 명령 중단 시 600ms 감시 정지 → ESTOP과
동작 그룹 중단을 지지 장치와 즉시 전원 차단 수단을 준비한 상태에서 확인해야 합니다.
이 단계는 실물 확인 이슈에서 결과·미통과 항목을 검토한 뒤 구체적인 명령을 제공합니다.

Pi에서 두 라이다와 영상이 동시에 동작할 때 CPU·메모리·온도·지연도 측정합니다.
실패를 숨기지 말고 `미실행`, `실패`, `측정 불가`를 그대로 적습니다.
