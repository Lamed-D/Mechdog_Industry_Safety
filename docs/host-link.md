# 호스트 로봇 링크와 MQTT 적용 경계

Python 공통 설정의 단일 출처는 `robot/config.py`, 와이어 상수·경고·역할 코드는 `robot/proto.py`입니다.
호스트는 이 순수 모듈만 가져오며 robot/main이나 하드웨어 모듈을 import하지 않습니다.
시간은 설정에서 ms로 두고 호스트 경계에서 초로 변환합니다. 포트·전압·역할 임대·송신/신선도 값을 서로 복사하지 않습니다.
실제 비밀번호·키는 여기에 넣지 않습니다. A/B ID는 업로드 생성기가 로봇별로 고정합니다.
카메라 C++와 메인 예비 판은 별도 언어 설정을 사용하며 계약 검증으로 차이를 확인합니다.

`host/robot_link.py`는 규약의 CMD/TEL을 그대로 사용합니다. 네트워크는 주입되는 send와 별도 UDP 어댑터입니다.
100ms마다 step을 호출하며 이동 의도는 300ms마다 갱신해야 합니다. 의도 만료·스캔 끊김·낮은 배터리·텔레메트리
400ms 지연은 새 이동을 차단하고 ESTOP을 래치합니다. 최초 연결 전에는 STOP/HELLO를 사용합니다.
1초 이상 텔레메트리가 없으면 상태는 unknown입니다.
로봇이 멈췄다고 추정하지 않습니다. 센서 유효성·신선도는 호출자가 판정한 뒤 mark_scan에 전달합니다.

RESET은 자동 전송하지 않습니다. 신선한 래치 상태와 배터리 조건을 확인하고 사용자가 명시적으로 요청해야 합니다.
ESTOP은 별도 요청으로 고정하며 RESET 후에도 이전 이동 의도를 복원하지 않습니다.
텔레메트리 순번이 늘어도 명령 ACK(last_seq)가 600ms 동안 진전하지 않으면 ESTOP을 래치합니다.
아직 보내지 않은 순번의 ACK나 역행 ACK는 신선도를 갱신하지 않습니다. 송신 예외도 같은 래치입니다.
연결 복구만으로 해제하지 않고, 신선한 로봇 래치 텔레메트리를 본 뒤 사람 RESET이 필요합니다.
600ms는 실측 전 보수적 초기값입니다. 두 방향 통신을 확인해야 하므로 우리 UDP 구조에 맞으며,
다른 센서·제어 펌웨어에 의존하지 않고 기존 TEL last_seq를 사용하도록 적용했습니다.
실제 RESET 허용 조건과 정지는 로봇이 최종 판단합니다. 네트워크 장애 시 호스트가 아닌 로봇의 600ms 감시가 정지합니다.

## 현재 PC에서 할 일

```bash
python -m unittest discover -s tests
python -m host.robot_link --help
```

실물 연결은 대상별 승인 후에만 합니다. 상태 전용 CLI도 HELLO/STOP을 송신하므로 단순 조회 명령으로 오해하지 않습니다.
기본 주소는 루프백이며 실제 IP는 `--allow-real`을 명시해야 열립니다. CLI에는 MOVE/RESET 기능이 없습니다.
A·B는 텔레메트리 포트가 같으므로 실제 운영은 하나의 수신 소켓에서 로봇 ID/주소로 분배해야 합니다.
두 CLI를 기본 포트로 동시에 실행하면 포트 충돌이 납니다. 이 어댑터는 단일 로봇 점검용입니다.

## 세션·순번 한계

HELLO의 boot_id가 되돌아오기 전에는 이동하지 않고, 중복·역행 텔레메트리는 신선도를 갱신하지 않습니다.
규약 v0 명령 본문에는 boot_id가 없습니다. 따라서 이전 세션의 지연 UDP 명령을 로봇이 완전히 구별할 수 없습니다.
전용 분리 네트워크와 명시적 RESET을 전제로 하며 이 한계를 인증·재전송 방지 완료로 표현하지 않습니다.
배포 전 세션을 포함하는 규약 확장 또는 검증 가능한 MQTT 봉투를 별도로 통합·검토해야 합니다.
UDP의 송신 IP/포트 확인은 인증을 대신하지 않습니다.

## MQTT 확장 준비

로봇 링크 핵심은 전송 라이브러리를 import하지 않아 UDP 대신 MQTT 어댑터를 붙일 수 있습니다.
현재 MQTT 브로커/클라이언트와 로봇 구독 루프는 구현·장치 검증하지 않았습니다. 내장 지원을 가정하지 않습니다.
제어 payload는 기존 CMD 내용을 유지하되 외부 봉투의 robot/session/sequence/expiry를 검증한 뒤에만 전달해야 합니다.
명령 retained 금지, clean session·오프라인 큐 폐기·중복/지연 거부·시간 동기화 실패 시 거부를 적용합니다.
QoS 1 재전송이 이동을 다시 실행시키지 않도록 순번을 유지합니다. 브로커 단절 시 600ms 감시를 리셋하지 않습니다.
실제 인증서·비밀값·브로커 계정은 사용자가 별도로 준비합니다. 공개 예시에 자격 정보를 넣지 않습니다.

Pi·브로커·두 대 실물 통신은 미검증입니다. 현재 tests는 주입한 전송과 가짜 시계로 규약·실패 경로를 검증합니다.
