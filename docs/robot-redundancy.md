# 동일 장비 두 로봇의 주·보조 역할 통신

로봇 A와 B는 같은 메인 보드·카메라·라이다를 각각 갖춥니다. A/B는 고정 장치 ID이며 주종 관계가 아닙니다.
주 역할(primary)과 보조 역할(secondary)은 Pi 5의 단일 조정자가 통신으로 배정합니다.
메인 보드는 공식 Python 제어를 그대로 쓰고 역할 때문에 장치 구성이 달라지지 않습니다.

## 역할 배정

1. Pi가 각 로봇과 서로 다른 세션 HELLO를 완료하고 신선한 TEL·배터리를 확인합니다.
2. 처음 두 로봇이 모두 가능하면 ID 순서로 주 역할을 정합니다. 이후 건강한 현재 주 역할을 유지합니다.
3. 주 로봇의 TEL이 400ms 이상 지연되거나 ESTOP/송신 장애·낮은 배터리가 있으면 후보에서 제외합니다.
4. 남은 로봇에 새 배정 세대(term)로 주 역할을 요청합니다. **일치하는 ACK 전에는 주 역할 미확인**입니다.
5. 이전 주 로봇이 복구돼도 역할을 빼앗지 않습니다. 사람 RESET과 상태 확인 뒤 보조 역할로 합류합니다.

모든 역할은 Pi가 알고 있는 현재 세대·세션의 응답으로만 유효합니다. 로봇끼리 독자적으로 주 역할을 선언하거나
움직이지 않습니다. **Pi 자체의 이중화는 제공하지 않습니다.** 네트워크 분리로 이전 로봇에 옛 주 역할 표시가
잠시 남더라도 Pi는 옛 세대 응답을 사용하지 않습니다. 이 표시를 장치 자체의 자율 구동 허가로 사용하면 안 됩니다.

## 와이어 형식

| 방향 | 형식 |
| --- | --- |
| Pi → UDP 9100 | `CMD\|ROLE\|<A/B>\|<seq>\|<host_boot_id>\|<term>\|<P/S/N>\|<lease_ms>\|$` |
| 로봇 → UDP 9101 | `ROLE\|<A/B>\|<host_boot_id>\|<term>\|<P/S/N>\|<remaining_ms>\|<tseq>\|$` |

P=주, S=보조, N=미지정. term은 1~2147483647, 임대는 100~1000ms입니다.
호스트는 기본 1000ms 임대를 약 300ms마다 갱신합니다. 다른 세션·낮은 세대·모순된 같은 세대·옛 명령 순번을 거부합니다.
ACK의 중복/역행 tseq는 역할 신선도를 갱신하지 않습니다. ACK는 TEL의 신선도를 대신하지 않습니다.
기존 CMD 최대 64바이트와 TEL 최대 160바이트는 유지하고 별도 역할 ACK를 사용합니다.
주·보조 역할과 발견/관리자 안내 같은 사건별 임무는 별개입니다. 이 단계는 역할 확인을 제공하며,
미완성 경로 계획을 대신해 이동하지 않습니다.

## 안전과 호환성

- 역할 배정은 부팅·ESTOP·저전압·통신두절 래치를 풀지 않습니다.
- 이미 역할을 받은 로봇에서 역할이 바뀌거나 임대가 만료되면 stop_action과 move(0,0)을 시도하고 link_lost로 래치합니다.
- 기존 600ms 명령 감시와 이동 유효시간을 유지합니다. 사람이 RESET하기 전 이전 이동을 복원하지 않습니다.
- HELLO 세션이 바뀌면 이전 역할을 버리고, 역할이 활성화돼 있던 로봇은 정지·래치합니다.
- 구형 호스트는 ROLE를 보내지 않습니다. 새 고정 위치 대시보드 어댑터는 역할 통신을 사용하며
  모든 이동·자세 명령을 차단합니다. **구형 로봇 코드는 ROLE를 잘못된 명령으로 보고 정지합니다.**
  사용자 업로드 시 호스트와 두 로봇의 코드를 함께 갱신해야 합니다.

출처 IP·포트와 세션·세대 확인은 인증·암호화가 아닙니다. 전용 분리 네트워크를 전제로 하며,
규약 v0 이동 명령에 세션이 없는 기존 한계도 남습니다. 공개망 제어에 사용하지 않습니다.

가짜 공식 모듈·시계로 배정·ACK·A 단절→B 승계·A 복구 시 B 유지·옛 응답 거부·임대 만료 정지를 검증했습니다.
실제 두 로봇의 Wi-Fi 지연·스케줄링·정지 시간은 미검증입니다. 장치 업로드·구동은 하지 않았습니다.
