# 허브 명령 처리기

`host.hub.commands.Processor`는 기존 command_envelope, CommandJournal, DashboardCore를 연결한다.
실제 서버 실행·네트워크·계정 없이 주입한 객체로 동작한다. 전체 정지를 배치에서 먼저 처리하며
같은 배치의 다른 조작은 거부한다. 만료된 전체 정지도 인증·형식 검사 후 실행한다.
전체 정지를 양쪽 링크로 시도한 다음 결과를 기록한다. 기록 실패가 정지를 막지 않는다.

authorize(device_id)는 신뢰한 최신 기기 레지스트리에서 권한을 반환하는 메모리 조회 함수다.
명령 본문의 권한 주장을 믿지 않는다. 실제 등록·권한 동기화는 후속 통합 대상이다.
UTC 신뢰 여부는 외부에서 주입하며 기본은 거부다. PostgreSQL의 +00:00 표기는 Z로 정규화한다.

일반 명령은 저널 예약 커밋 뒤에만 실행한다. 예약 후 다시 만료를 검사한다.
같은 ID의 다른 내용과 기록 실패는 거부한다. 재시작 시 reserved는 자동 실행하지 않으며
사람의 상태 확인과 새 명령이 필요하다. 정확히 한 번 실행을 보장한다고 주장하지 않는다.
accepted는 봉투와 예약 통과, operator의 done은 시나리오 의도 접수이며 물리 이동 완료가 아니다.

RESET은 confirmed=true와 현재 상태를 묶는 공개 확인 ID가 필요하다. 이 ID는 인증 수단이 아니다.
기존 개발 화면처럼 5초·단일 사용이며 새 ESTOP, 부팅 ID, 래치 사유 변경으로 무효화한다.
reset_contexts() 값을 상태에 올리고 화면에서 확인한 값을 다시 명령에 넣는다.
실제 래치 해제는 신선한 텔레메트리의 unlatched를 확인한 뒤에만 done으로 기록한다.
확인 중 새 정지·부팅 또는 명령 기한 종료는 rejected다. 연결 복구로 RESET을 만들지 않는다.

서비스는 제어 작업자와 동일한 lock을 넘긴다. 저널과 outbox는 lock 밖에서 접근한다.
DashboardCore의 로그는 운영 시 BufferedEventLog를 사용해야 한다. 현재 단위는 처리기만 구현하며
서비스 루프·원격 상태 게시·권한 갱신·실제 장비·Supabase/RLS는 미검증이다.
결과 대기열 실패는 report_failures로 드러나며 기존 명령 예약은 유지된다.
