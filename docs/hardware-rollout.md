# 장비 도착 전·후 적용 계획

## 현재 장비와 원칙

MechDog 본체와 장착된 비전 모듈을 우선 사용합니다. 본체는 ESP32 계열 메인 컨트롤러,
비전은 별도 ESP32-S3 모듈입니다. 본체용 MicroPython과 카메라용 펌웨어를 혼동하지 않습니다.
Pi 5·A1M8·추가 부품은 미수령 상태로 취급합니다. 약 일주일 뒤 도착 예상은 계획이며 검증 완료가 아닙니다.

| 단계 | 자동으로 준비하는 것 | 사용자만 할 일 | 다음 단계 조건 |
| --- | --- | --- | --- |
| 지금 | 공식 Python 카메라 연결·가짜 모듈·실패 경로 테스트 | 본체 API·배터리·카메라 읽기 승인과 관측 | A/B별 결과 확인 |
| 도착 전 | ROS 스캔 변환·로봇 링크·MQTT 설계·모의 시나리오·설정 예시 | 추가 장비 없이 수행 가능 | 합성 테스트 통과 |
| Pi 수령 | 설치 명령과 두 로봇 설정 분리 | OS 설치·냉각·전원·전용 네트워크 구성 | Pi에서 합성 테스트와 ROS 통신 성공 |
| 라이다 수령 | 전송 형식·무효값·신선도 검증 코드 | 커넥터·핀·별도 전원·UART 루프백·USB 단독 확인 | 전압·전류·방향·health 확인 |
| 통합 | 전체 경로 모의 연동·경고·기록 | 펌웨어 업로드와 지지 상태의 제한 구동 별도 승인 | 600ms 감시·ESTOP·RESET·영상·부하 검증 |

## A1M8 적용 기준

공개 데이터시트로 UART 115200bps 8N1, 코어 4.9~5.5V, 동작 300~350mA·기동 최대 600mA,
모터 5V 약 100mA, 거리 0.15~12m(흰색 대상 조건)을 대조했습니다.
코어에는 9V를 공급하지 않습니다. 첫 시험은 모터도 5V로 하고 고속 회전을 시도하지 않습니다.
RX는 입력 특성이 별도로 있으므로 임의 직렬 저항이나 전압 변환을 추가하지 않고 배선 설계를 먼저 확인합니다.
데이터시트의 측정 성능과 5바이트 표준 패킷의 UART 전송량은 구분합니다.
실제 커넥터 핀 방향은 문서 도형과 장치 실물을 함께 확인해야 하며 화면의 좌우만 보고 꽂지 않습니다.

## MQTT 적용 판단

현재 제조사 Python 예제에서 확인한 카메라 연결은 공식 IIC API입니다. MQTT 기본 내장 지원은 아직 확인하지 못했습니다.
MQTT를 위해 카메라의 Arduino 펌웨어로 교체하거나 raw I2C 제어를 도입하지 않습니다.
초기 구조는 Pi 쪽 전송 어댑터에서 MQTT를 선택할 수 있게 설계하고, 장치 라이브러리 지원·지연·복구 시험 후 채택합니다.

명령 토픽은 로봇별로 분리하고 retained 제어 명령을 금지합니다. 세션 식별자와 발행 시각·유효시간,
중복/재전송·재접속 처리·인증/ACL·브로커 단절을 검증해야 합니다. QoS는 순번·만료 검증을 대신하지 않습니다.
로봇 자체의 600ms 감시와 ESTOP `stop_action()`+`move(0,0)`은 전송 방식과 관계없이 유지합니다.
브로커 Last Will은 상태 표시용이며 로봇 정지를 대신하지 않습니다. 카메라 영상은 제어 MQTT 토픽에 싣지 않습니다.

## 아직 확인하지 않은 것

장치 펌웨어 API 존재·호출 시간, 비전 기능 모드·원본 영상 전송 경로, Pi 성능,
동작 시간·배터리 임계·라이다 신호 방향·두 대 동시 Wi-Fi 지연·MQTT 장치 클라이언트 지원은 실물 미검증입니다.
확인 결과는 [사용자 테스트](user-tests/README.md) 양식과 이슈에 남기고 설정을 갱신합니다.
