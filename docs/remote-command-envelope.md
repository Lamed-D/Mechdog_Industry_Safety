# 원격 조작 봉투 초안 v1

`host/command_envelope.py`는 원격 JSON을 검사하며 실행하지 않습니다.
Supabase 계정·키·테이블·RLS를 만들거나 접속하지 않았습니다. 실제 서버 연결 전용의 검증 초안입니다.
현재 로컬 대시보드 API와 로봇 UDP 규약을 바꾸지 않습니다.

봉투는 최대 4096바이트이고 다음 필드만 받습니다.

| 필드 | 의미 |
| --- | --- |
| `v` | 정수 1 |
| `id` | 소문자 표준 UUID, 중복 전달 식별 |
| `hub_id`, `device_id` | 목적 Pi·인증된 조작 기기 ID, 영숫자/밑줄/하이픈 1~64자 |
| `robot_id` | reset은 A 또는 B, 전체 estop/operator는 null |
| `kind` | estop / reset / operator / map_confirm |
| `created_at`, `expires_at` | UTC `YYYY-MM-DDTHH:MM:SS[.ffffff]Z`, 수명 0초 초과~10초 이하 |
| `payload` | estop은 빈 객체, reset은 confirmed=true와 reset_context, operator는 별도 허용된 event만 |

기기 ID·허용 권한은 인증 채널에서 얻어 함수에 별도로 전달합니다. 본문의 ID나 확인 표시는 인증이 아닙니다.
본문만 보고 권한을 만들어 넘기면 안 됩니다. JSON 중복 키·여분 필드·이동/주종 문자열 대상은 거절합니다.
A/B는 장비 ID이며 변할 수 있는 주·보조 역할을 조작 대상 ID로 사용하지 않습니다.

정지를 제외한 조작은 신뢰 가능한 UTC가 확인돼야 하며 미래·만료 시각은 거절합니다.
전체 정지는 유효한 봉투·목적지·인증·권한을 확인한 뒤 지연·시각 미동기화에도 허용합니다.
reset의 confirmed=true만으로 로봇 래치를 풀지 않습니다. 실행 계층은 신선한 TEL·배터리·현장 사람 확인을 다시 검사해야 합니다.
reset_context는 실행 서비스가 발급한 공개 상태 확인 ID이며 현재 로봇의 새 정지·세션·만료·사용 여부를 실행 직전에 재검사해야 합니다.
봉투 검사는 이 ID의 형식만 검사합니다. 원격 동기화에는 아직 연결하지 않았습니다.
정찰 조종·루틴 명령은 거절하며 수명 0.5초 조종 구현은 남아 있습니다.
지도 확정은 `map_confirm`으로 추가했습니다. 대상은 null, payload는 `base_map_id`, `proposal_map_id`(서로 다른 UUID),
`base_sha256`, `proposal_sha256`(원본 파일 해시), `approved_clearings`(중복 없는 셀 인덱스 최대 128개)만 받습니다.
128개는 4096바이트 봉투 크기를 지키기 위한 전송 제한이며 물리 안전 값이 아닙니다. 초과 시 작은 제안본으로 다시 검토합니다.
허브는 다운로드 뒤 만료·현재 권한을 재검사하고 안전 검토한 지도 확정 행만 outbox에 넣습니다.
`done/map_confirmation_queued`는 확정 행 대기열 접수이며 클라우드 반영·설정 활성화·주행 허가가 아닙니다.

`ReplayWindow`는 단조 시계 기준 10초 동안 처리한 ID를 기억합니다. 가득 차면 기존 기록을 밀어내지 않고 거절합니다.
전체 정지는 중복이어도 허용합니다. 이 메모리 창은 프로세스 재시작 후 중복 실행을 막는 영속 저널을 대신하지 않습니다.
`CommandJournal`은 SQLite에서 처리 ID·봉투 해시를 실행 전에 reserved로 원자 예약하고 결과를 별도로 기록합니다.
같은 ID의 다른 봉투, 용량 초과, 디스크 오류는 새 실행을 허용하지 않습니다. 같은 ID는 완료 여부와 관계없이 다시 예약하지 않습니다.
재시작 후 reserved는 실행 여부 불명이며 자동 재실행하지 않습니다. 사람은 로봇 TEL·상태를 확인하고 새 조작을 판단해야 합니다.
예약 커밋 직후 실행 전 종료되면 명령이 실행되지 않을 수 있습니다. 중복 실행 방지를 위해 누락 가능성을 택한 것이며 정확히 한 번 실행을 보장하지 않습니다.
reset의 done은 TEL로 해제를 확인한 뒤에만 기록해야 하며 송신 성공만으로 done을 기록하면 안 됩니다.

저널은 WAL·synchronous=FULL을 사용합니다. 하드웨어·파일시스템의 동기화 보장은 실제 Pi에서 별도 확인해야 합니다.
근거: [SQLite 동기화 설정](https://www.sqlite.org/pragma.html#pragma_synchronous),
[쓰기 트랜잭션](https://www.sqlite.org/lang_transaction.html).
최대 100,000건이며 자동 삭제하지 않습니다. 보존/아카이브 정책을 정하기 전 포화 시 정지 외 조작을 거절합니다.
전체 정지는 이 저널을 기다리지 않고 먼저 전송하고 별도 비차단 사건 기록을 남겨야 합니다. 저널은 estop 예약을 거절합니다.
네트워크 조회·인증·디스크 기록은 10Hz 제어 잠금 밖에서 해야 합니다.

미완료: 인증된 기기 권한/RLS, 시계 동기화 확인, 명령 결과 동기화, 이벤트 실행 연결.
이 단계가 끝나기 전에는 봉투 검사 성공을 실제 조작 허가로 사용하지 않습니다.
