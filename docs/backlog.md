# 개선 작업 기록

실물 업로드·굽기·구동은 사용자만 수행합니다. 합성 테스트 통과는 실물 검증을 뜻하지 않습니다.

## 완료

- 시작 확인: codex1 준비 완료, 비공개 목록 존재만 확인, 인증·fetch 완료. 시작 브랜치 변경 없음.
- 기존 PR은 모두 병합 또는 닫힘. 원격에는 main만 있어 삭제할 종료 브랜치 없음.
- 기준 전체 unittest 218개 통과.
- 동작 시작 직후 예외, 상태에 없는 동작의 ESTOP, 루프 종료를 장애 주입으로 재현하고 정지 경로 보강.
  모든 래치에서 stop_action을 시도하고 실패해도 move(0,0)을 호출합니다.
- 제조사 예제·순정 문자열의 공식 API 대조표, A/B 단일 main 생성 도구, 사용자 업로드·복구 순서 추가.
- 명령 ACK가 멈춘 단방향 장애·텔레메트리 지연·송신 예외에서 호스트 ESTOP 래치 보강.
- 카메라 v0.1.2: 접속 전 프레임·카메라 오류 프레임 거부, JPEG 끝 검사, HTTP 등록 실패 재시도.
  Pi 수신 A/B 식별·캡처 나이·중복 순번·연결 종료 처리를 가짜 서버로 검증.
- 대시보드 고정 위치 점검 어댑터: 한 UDP 소켓 A/B 분배, 출처 검증, 전체 정지·사람 RESET.
  이동·동작·자세는 명시적으로 차단하며 실물 모드는 사용자 토큰 필수. 실제 송신은 미실행.
- 카메라 v0.1.3: 제조사 품질·순정 문자열 재조사, VGA 품질10/15fps와 SVGA 품질10/10fps 프로필,
  실제 취득 시각·JPEG 대역 지표, 최신 합본·해시·manifest만 build에 유지. 이전 배포 bin 제거.
  기본·세부 프로필 컴파일 성공. 기본 앱 1,019,824바이트, 합본 1,085,360바이트. 전체 unittest 240개 통과.
- 동일 장비 A/B의 주·보조 역할 배정·임대·세션/세대 ACK 통신 구현. Pi 단일 조정자로 A 단절 시 B에 역할을 배정하며,
  복구 A가 역할을 빼앗지 않습니다. 역할 변경·임대 만료는 정지·래치, 자동 RESET·이동 없음.
- 최신 JPEG 추론 작업자·제어 루프 결과 적용 경계 추가. 모델 미설치·오류·낮은 해상도·지연 결과는 unknown.
  영상 단절 시 호출·안내 정지와 사람 재시도, unknown 상태의 새 순찰 차단을 회귀 검증.

## 남은 소프트웨어 작업

1. 공식 API 실물 인자·단위 확인과 단일 main의 MicroPython 힙 검증(사용자).
2. 고정 위치 어댑터 다음 단계: 경로·동작 통합과 역할별 사건 임무 정책. 실물 정지 확인 전 이동 차단 유지.
3. 카메라 실제 화질·수신·모델 추론 성능 측정(사용자), 합성 성능 측정 도구 보강.
4. 감지 수신 연결과 시간 창 근거, 모델·라이선스·Pi 성능 근거.
5. 하드웨어·버스·주소 표와 읽기 전용 API 후보 점검 도구.
6. Arduino 예비 판 설계·최소 골격, 사건 기록·설정·장애 주입 보강.
7. 사용자 단계별 확인 패키지와 통합 데모.

## 위험·확인 필요

- 빌드 루트의 구형 중간 산출물 일괄 정리는 실행 정책이 차단해 보류했습니다. 우회하지 않았습니다.
  최신 사용자 배포물은 build/vision_cam/latest의 manifest와 해시로 구분합니다.
- 주·보조 역할의 실제 갱신·승계·대시보드 표시를 두 로봇으로 확인해야 합니다.
  합성 통합 테스트 포함 전체 247개 통과. 사용자 코드 갱신은 호스트와 두 로봇을 함께 진행합니다.

- stop_action의 실제 정지 지연과 공식 API의 블로킹 시간은 실물에서 확인해야 합니다.
- 호스트 가짜 테스트는 MicroPython 스레드 스케줄링·잠금 지연을 검증하지 못합니다.
- 전원 여유, 라이다 기동 전류·고정 상태, 카메라 센서·플래시·PSRAM 실측이 필요합니다.
- 물리 작업은 본체/카메라 백업 → 대상별 업로드/굽기 → 읽기·영상·정지 확인 → 문제 시 백업 복구 순서입니다.
  기존 사용자 전용 이슈 #29·#30·#44는 계속 열어 둡니다.
