# 시연 시나리오: 쓰러진 사람 발견 → 관리자 알림 → 관리자 안내

## 1. 한 줄 요약

로봇 **2대**가 현장을 지키다가, 카메라로 **쓰러져 있는 사람**을 발견하면 **대시보드로 관리자에게 알리고**,
2대 중 1대가 **관리자가 있는 곳(사무실 등 미리 정한 위치)** 으로 가서 관리자를 **쓰러진 사람에게 안내**해
조치하게 합니다.

## 2. 등장 요소

| 요소 | 역할 |
| --- | --- |
| 로봇 A (발견 로봇) | 순찰하면서 앞쪽 비전 모듈로 쓰러진 사람을 찾음. 발견하면 멈추고 알림을 보낸 뒤 그 자리에서 대기·신호 |
| 로봇 B (안내 로봇) | 알림을 받으면 관리자 위치로 이동해 관리자를 사고 지점까지 안내 |
| 대시보드 | 관리자에게 알림 표시(어느 로봇, 어디서, 언제), 관리자가 확인·조치 완료를 누름 |
| Raspberry Pi 5 16GB (고정 위치) | 두 로봇의 라이다·카메라 데이터를 받아 지도 작성, 자기 위치, 경로 계획, 쓰러진 사람 감지, 대시보드 서버. 부족하면 Jetson Orin Nano Super로 처리 |
| RPLIDAR A1M8-R6 (로봇마다 등 위에 테이프 고정) | 360° 거리 측정 → 지도·자기 위치·장애물·사람 감지 보조 |
| 관리자 위치 | 사무실 등 **미리 정해 둔 특정 위치** 하나(시연에서는 가정) |
| 쓰러진 사람 | 시연에서는 사람 또는 대체물(마네킹·사진 등, 아래 결정 사항) |

- 두 로봇은 같은 구성입니다(다리 4개, 앞쪽 비전 모듈, 팔 없음 — [MechDog 제어 API 규칙](dev/mechdog-api.md) 0절).
- 어느 로봇이 A·B인지는 고정하지 않아도 됩니다. **발견한 로봇이 A**, 다른 한 대가 B가 됩니다
  (시연을 단순하게 하려면 A·B를 고정해도 됨 → 결정 사항).

## 3. 흐름

```text
[순찰] 로봇 A·B 순찰 또는 대기
   │
   ▼
[발견] 로봇 A 카메라에 쓰러진 사람 감지
   │   → 로봇 A 즉시 정지(mechdog.move(0, 0)), 사람과 거리 유지
   │
   ▼
[알림] 로봇 A → 대시보드: 로봇 ID, 위치(구역), 시각, 감지 근거·신뢰도
   │   대시보드: 관리자 화면에 경고 표시
   │   로봇 A: 현장에서 대기, 부저·자세로 주변에 신호
   │
   ▼
[호출] 대시보드 → 로봇 B: "관리자 위치로 이동 후 안내" 명령
   │
   ▼
[이동] 로봇 B → 관리자 위치로 이동, 도착하면 신호(끄덕이기·부저)
   │
   ▼
[안내] 관리자가 확인(대시보드 버튼 등) → 로봇 B가 앞장서서 사고 지점까지 천천히 이동
   │   관리자와 떨어지면 멈추고 기다림
   │
   ▼
[조치] 사고 지점 도착 → 로봇 B 정지·앉기, 관리자 조치
   │   관리자가 대시보드에서 "조치 완료" → 로봇 A·B 순찰/대기로 복귀
```

## 4. 단계별 동작 (공식 API 기준)

| 단계 | 로봇 | 동작 | 사용하는 API (mechdog-api.md) |
| --- | --- | --- | --- |
| 순찰 | A·B | Pi 5가 정한 경로로 이동 | `move`, `set_gait_params`(작고 빠른 걸음 등) |
| 발견 | A | 즉시 정지 | `mechdog.move(0, 0)` |
| 신호 | A | 주변에 위험 알림 | `Hiwonder.Buzzer().playTone(...)`, `action_run("nodding_motion")` |
| 대기 | A | 낮은 자세로 대기 | `action_run("sit_dowm")` 또는 `set_default_pose()` |
| 이동 | B | 관리자 위치로 이동(Pi 5가 라이다 지도로 경로 지시) | `move` |
| 도착 신호 | B | 관리자 주의 끌기 | `action_run("nodding_motion")`, 부저 |
| 안내 | B | 느린 걸음으로 앞장서기 | `set_gait_params(150, 500, 40)`(크고 느린 걸음), 작은 `move` 보폭 |
| 도착 | B | 정지·앉기 | `mechdog.move(0, 0)`, `action_run("sit_dowm")` |
| 복귀 | A·B | 기본 자세 후 순찰 | `set_default_pose()` |

- 시연 전용 동작(두 발 서기, 발차기 등)은 쓰지 않습니다.
- 모든 이동 반복문은 예외·통신 끊김·센서 실패 시 `mechdog.move(0, 0)`으로 끝납니다.

## 5. 대시보드

| 기능 | 내용 |
| --- | --- |
| 알림 표시 | 로봇 ID, 위치(구역), 발견 시각, 감지 근거·신뢰도, 가능하면 현장 사진 |
| 로봇 상태 | 각 로봇의 현재 단계(순찰/발견/이동/안내/대기), 마지막 통신 시각 |
| 관리자 조작 | 알림 확인, 안내 시작, 조치 완료, (비상) 전체 정지 |
| 기록 | 알림·조작 이력 |

- 대시보드의 **전체 정지** 버튼은 두 로봇 모두 즉시 `move(0, 0)` 하게 합니다.
- 로봇과 통신이 끊기면 대시보드에 바로 표시하고, 로봇은 스스로 정지합니다.
- 현장 사진에는 사람이 찍히므로 시연 외 용도로 저장·커밋하지 않습니다(ai-guide 3절).

## 6. 안전 규칙 (시연)

1. 로봇은 **쓰러진 사람에게 닿지 않습니다.** 발견 즉시 정지하고, 다가가는 동작을 넣지 않습니다.
2. 감지가 불확실하면 **알림은 보내되 "확인 필요"로 표시**합니다. 오탐을 숨기거나 확정처럼 알리지 않습니다.
3. 안내 중 관리자와 떨어지거나, 앞에 장애물이 있거나, 통신이 끊기면 **멈추고 기다립니다.**
4. 실제 시연 전 리허설은 사람 대신 대체물로 먼저 합니다.
5. 실제 로봇 실행·업로드는 사용자 확인 후에만 합니다([에이전트 협업 규칙](dev/agents.md)).

## 7. 시스템 구성

```text
 로봇 A ─┐  라이다 데이터, 카메라 영상          ┌─ 지도·자기 위치(SLAM), 경로 계획
 로봇 B ─┤ ───────── Wi-Fi ─────────▶ Pi 5 ──┼─ 쓰러진 사람 감지
         │ ◀──── 이동·정지·동작 명령 ──────    └─ 대시보드 서버 ──▶ 관리자 화면
```

- 로봇(ESP32)은 공식 API로 움직이기만 하고, 판단은 고정 위치의 Pi 5가 합니다.
- 통신이 끊기면 로봇이 스스로 정지합니다([mechdog-api.md](dev/mechdog-api.md) 9절).

## 8. 결정 사항

| 항목 | 결정 | 상태 |
| --- | --- | --- |
| 처리 컴퓨터 | Raspberry Pi 5 16GB, **고정 위치**(로봇에 싣지 않음). 부족하면 Jetson Orin Nano Super | 결정 |
| 위치·지도·이동 | RPLIDAR A1M8-R6를 로봇 등에 **테이프로 고정**, Pi 5에서 SLAM으로 지도·자기 위치·경로 | 결정 |
| 쓰러진 사람 감지 | Pi 5에서 카메라 영상(+ 라이다 보조)으로 판단 | 결정, 방법 세부는 미정 |
| 로봇 A ↔ B 연동 | Pi 5가 중계 | 결정 |
| 로봇 ↔ Pi 5 통신 | Wi-Fi. 내장 Wi-Fi로 충분한지, 브리지·전용 공유기가 필요한지 검토 중 | **검토 중** |
| 라이다 → Pi 5 연결 | 로봇 쪽에 라이다를 받아 Wi-Fi로 보낼 장치가 필요 | **검토 중** |
| 카메라 영상 → Pi 5 | 비전 모듈(ESP32-S3) 영상을 Pi 5가 받을 수 있는지 확인 필요 | **확인 필요** |

## 9. 아직 정해야 할 것

| 항목 | 문제 | 후보 |
| --- | --- | --- |
| 관리자 따라오는지 확인 | 카메라는 앞쪽뿐 | 라이다로 뒤쪽 사람 다리 감지 / 일정 거리마다 멈추고 대시보드 확인 |
| 라이다 높이와 쓰러진 사람 | 등 위 라이다의 스캔 평면보다 누운 사람이 낮을 수 있음 | 카메라 판단 위주, 라이다는 위치·장애물용 |
| A·B 역할 | 고정할지, 발견한 쪽이 A가 될지 | 시연은 고정 권장 |
| 대시보드 형태 | 웹 / PC 프로그램 | Pi 5의 웹 대시보드 권장 |
| 쓰러진 사람 대체물 | 리허설·시연용 | 사람 / 마네킹 / 인쇄물 |
