# 사용자용 비전 모듈 펌웨어 확인·업로드 가이드

이 문서는 **장착된 ESP32-S3 카메라 모듈**만 대상으로 합니다. 업로드는 사용자가 수행합니다.
MechDog 메인 보드의 펌웨어·main.py·boot.py는 변경하지 않습니다. 이동·정지·자세·동작 API도 실행하지 않습니다.

## 1. 현재 결과와 먼저 할 확인

사용자 제공 진단 결과:

```text
VISION_STAGE iic_init
VISION_STAGE camera_init
VISION_METHODS ['face_recognition', 'color_recognition']
VISION_STAGE face_read
VISION_RESULT ... 'errno': 19 ... 'status': 'unknown' ...
```

공식 라이브러리와 메서드는 존재하지만 **얼굴 결과 읽기는 실패**했습니다. 생성자가 실제 장치 응답까지
확인했다고 볼 수 없습니다. 얼굴이 없다는 정상 결과가 아니며, 카메라 고장이나 펌웨어 오류로 단정할 수도 없습니다.

아래 순서로 확인하고, 전원·케이블 문제가 해결되면 펌웨어를 바꾸지 않고 다시 시험합니다.

먼저 최신 진단 버전 2에서 `VISION_METHOD_SELECTED read_face`가 나오는지 확인합니다.
제조사 Python 얼굴 강좌의 실제 프로그램은 `read_face()`를 사용합니다.
이전 배포의 `face_recognition()`만 실패한 결과로 펌웨어 변경을 결정하지 않습니다.
최신 메서드가 없을 때만 이전 이름을 선택하며, 읽기 실패를 숨기기 위해 다른 메서드를 자동 재시도하지 않습니다.

1. 본체 전원을 끄고, 카메라와 메인 보드의 공식 IIC 케이블이 양쪽 모두 연결됐는지 확인합니다.
   제조사 얼굴 강좌의 연결 그림은 **본체 물리 IIC 포트 1**입니다. Python의 **`IIC(2)`와 대응**하며
   코드의 숫자 2를 보고 본체의 포트 2에 꽂는 것이 아닙니다.
2. 커넥터 방향·손상·느슨함을 제조사 조립 그림과 대조합니다. 전원이 켜진 상태에서 케이블을 바꾸지 않습니다.
3. 카메라의 전원 상태를 확인합니다. 제조사 권장 공급 조건은 5V 2A 이상입니다. 임의로 핀에 전원을 넣지 않습니다.
4. 현재 카메라 펌웨어가 영상 전송용인지 얼굴 인식용인지 확인합니다. 모르면 `미확인`으로 기록합니다.
5. 전원을 다시 연결하는 작업은 사용자가 직접 합니다. 본체 기존 main.py가 자동 동작할 수 있으므로 먼저
   지지·격리와 기존 프로그램 중지 방법을 확보합니다. 에이전트가 본체를 재부팅하지 않습니다.

## 2. 어떤 기능을 시험하는가

| 목적 | 카메라 펌웨어 역할 | 확인 방법 |
| --- | --- | --- |
| 현재 공식 Python 얼굴 API 읽기 | 제조사 얼굴 인식 기능용 | 메인 보드에서 vision_probe 실행 |
| 나중에 Pi에서 원본 영상으로 낙상 추론 | 제조사 영상 전송 기능용 | 실제 지원 주소·형식·fps 확인 후 호스트 연결 |
| 색·선 인식 | 각 기능에 맞는 제조사 펌웨어 | 해당 공식 Python 예제로 별도 승인 후 확인 |

제조사 배포에는 기능별 바이너리가 따로 있습니다. **한 가지 펌웨어에서 영상 전송과 모든 인식 기능이
동시에 된다고 가정하지 않습니다.** 기본 영상 전송 상태라면 얼굴 API를 읽을 수 없는 원인 후보입니다.
현재는 얼굴 API 연결 시험이며 얼굴 검출은 낙상 감지 기능이 아닙니다.
다른 확장 모듈이나 AI 플랫폼 전환용 펌웨어를 카메라에 올리지 않습니다.

## 3. 업로드 전 체크리스트

- [ ] 대상이 MechDog 메인 보드가 아닌 **ESP32-S3 카메라 모듈**임을 확인했습니다.
- [ ] 현재 기능과 복구에 사용할 제조사 정식 바이너리를 확보했습니다. 현재 모드를 모르거나 복구 파일을 모르면 중단합니다.
- [ ] 사용자 boot/main 사본은 [백업 보관](../backups/device-original/README.md)에 있습니다.
      이는 **메인 보드 시작 파일 사본**이며 카메라 플래시 전체·설정·보정값의 백업이 아닙니다.
- [ ] 본체 전원을 끄고, 제조사 지침에 따라 카메라를 별도로 연결할 수 있게 준비했습니다.
      USB와 본체 전원의 이중 공급·역급전 가능성을 확인하지 못했으면 동시에 연결하지 않습니다.
- [ ] 카메라의 Type-C **데이터 케이블**을 사용합니다. 충전 전용 케이블은 사용할 수 없습니다.
- [ ] 카메라를 뺐다 꽂을 때 생기고 사라지는 COM 포트를 확인했습니다.
      기존 COM6은 메인 보드 연결에서 확인된 번호이므로 카메라 포트라고 가정하지 않습니다.
- [ ] 에디터·시리얼 모니터 등 카메라 COM 포트를 잡는 프로그램을 닫았습니다.
- [ ] 올릴 파일이 카메라의 정확한 모델·기능에 맞는 제조사 바이너리임을 확인했습니다.

## 4. 제조사 제공 비전 바이너리의 수동 다운로드

아래 설정은 제공된 **비전 모듈 전용 통합 바이너리 안내**에서 확인한 값입니다.
다른 패키지·모델·분할 바이너리라면 이 값을 재사용하지 말고 그 배포물의 지침을 따릅니다.
실제로 플래시를 수행하거나 장치에서 검증한 설정은 아닙니다.

1. 사용자가 제조사 제공 플래시 다운로드 도구를 실행합니다. 관리자 권한이나 드라이버 설치 요청은 사용자가 판단합니다.
2. `ChipType`을 **ESP32-S3**로 선택합니다. 메인 보드의 일반 ESP32용 설정과 혼동하지 않습니다.
3. 현재 시험 목적에 맞는 **얼굴 인식용 비전 바이너리** 하나를 선택합니다.
   옆 체크박스를 켜고 주소는 해당 통합 바이너리 안내의 **0x0000**을 사용합니다.
4. 해당 안내의 설정을 확인합니다:

   | 도구 항목 | 제공된 비전 바이너리 안내 값 |
   | --- | --- |
   | SPI SPEED | 80MHz |
   | SPI MODE | DIO |
   | BAUD | 460800 |
   | COM | 위에서 직접 식별한 카메라 전용 포트 |
   | 나머지 | 해당 안내의 기본값 유지 |

5. 선택한 파일·주소·칩·COM을 다시 대조한 다음 사용자가 `START`를 누릅니다.
   **임의의 ERASE나 전체 플래시 삭제는 하지 않습니다.** 필요하다는 정확한 비전 지침과 복구 수단이 있을 때만 별도로 판단합니다.
6. 완료 표시와 오류 유무를 확인합니다. 쓰는 도중 USB를 빼거나 전원을 끄지 않습니다.
7. 연결 실패라면 포트 점유·케이블·대상 칩을 먼저 확인합니다. BOOT/다운로드 모드 버튼 조합은 보드별로
   다를 수 있어 이 문서에서 추측하지 않습니다. 해당 모듈 지침과 버튼 표시를 확인한 뒤 진행합니다.
8. 업로드 후 카메라 전원을 분리하고, 본체 전원이 꺼진 상태에서 공식 IIC 케이블을 원래대로 연결합니다.
   본체 복귀·전원 조작은 사용자가 수행하며 메인 보드 파일은 덮어쓰지 않습니다.

## 5. 업로드 뒤 비전만 재확인

메인 보드 에디터를 실제 메인 보드 포트에 연결합니다. 현재 기록은 COM6이지만 재연결 때 번호가 바뀌면 다시 확인합니다.
현재 main.py는 모션 초기화를 포함하므로 **Download and Run / Reset / 빈 REPL의 Ctrl+D를 사용하지 않습니다.**
`raw REPL`이면 Ctrl+B로 일반 `>>>`로 돌아옵니다.

최신 [vision_probe.py](../tools/bringup/vision_probe.py)만 사용합니다. 기존 main.py나 boot.py로 이름을 바꾸지 않습니다.
진단 파일 준비가 필요하면 **Download만** 선택하고 자동 재부팅 옵션이 보이면 진행하지 않습니다.
단순 Download도 현재 에디터에서 재부팅을 유발한다면 업로드를 중지하고 REPL 붙여넣기 방식으로 전환합니다.

일반 REPL에서 사용자가 실행할 명령:

```python
exec(open('vision_probe.py').read(), globals())
```

| 결과 | 해석 / 다음 행동 |
| --- | --- |
| `observed`, `has_result=False` | 호출이 결과를 반환함. 현재 장면에서 인식 결과가 없는 것일 수 있음 |
| `observed`, `has_result=True` | 인식 결과가 있음. 낙상 검증 완료는 아님 |
| `unknown`, `face_read`, `errno=19` | 인식 읽기 실패 지속. 모드·IIC 케이블·전원을 재확인하고 무작정 재플래시하지 않음 |
| `camera_api_missing` | 메인 보드 공식 라이브러리 지원 확인이 필요. 카메라만 플래시해 해결된다고 가정하지 않음 |
| `IndentationError` | 진단 파일/붙여넣기 손상. 하드웨어 검사 전 파일을 복구 |

오류가 지속되면 같은 공식 파일을 반복해서 올리지 말고 아래 결과를 보고합니다.

## 6. 사용자 결과 보고

실물 확인 이슈 #29에 다음만 남깁니다:

- 대상 로봇 A/B, 카메라 모델 표시, IIC 케이블 양쪽 연결 확인 여부
- 업로드 전/후 기능 모드와 사용한 제조사 기능 종류(얼굴 인식 / 영상 전송 등)
- 칩·주소·속도·모드, 카메라 포트를 직접 식별했는지 여부
- 완료/실패 표시와 진단 stage·errno·read_ms·status·result_type·has_result
- 예상치 못한 재부팅·발열·전원 불안정 여부와 중단 조치

실제 얼굴 영상·사진·Wi-Fi 비밀번호·토큰·장치 일련번호·개인정보는 첨부하지 않습니다.
성공한 뒤에도 원본 영상→Pi 추론 경로는 별도 시험입니다. 아직 Pi·라이다가 없어 현재는 카메라 공식 Python 읽기만 확인합니다.
