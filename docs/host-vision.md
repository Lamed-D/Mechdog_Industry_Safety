# 장착 비전 모듈과 호스트 감지 경계

카메라는 장착된 ESP32-S3 모듈을 사용합니다. MechDog 공식 Hiwonder Python 연결은
`robot/vision.py`의 `ESP32S3Cam(IIC(2))`이며 최신 제조사 얼굴 예제의 `read_face()`를 우선 사용합니다.
이전 메서드만 있는 장치에서는 `face_recognition()`을 사용하고 결과 유형·존재만 진단합니다.
제조사 연결 그림의 본체 물리 IIC 포트 1이 코드 IIC(2)에 대응합니다.
메인 보드와 비전 보드의 펌웨어는 다릅니다. 카메라를 다른 보드로 교체하거나 Arduino로 전환하는 절차가 아닙니다.

## 현재 실행 가능 범위

- PC: `python -m unittest discover -s tests`로 합성 관측·오류·무응답·신선도 검증.
- 사용자 승인 후 MechDog: [본체·카메라 읽기 점검](user-tests/current-hardware.md).
- Pi·실제 영상 추론: 대기. 원본 영상의 지원 경로·주소·형식은 사용자 확인이 필요합니다.

공식 얼굴·색 인식 결과는 원본 프레임이나 낙상 자세 정보가 아닙니다.
얼굴 검출 성공을 쓰러진 사람 검출로 보고하지 않습니다. HTTP 경로를 추측하거나 공식 I2C 장치를 raw 드라이버로 읽지 않습니다.

`host/vision/evidence.py`는 추론 어댑터가 제공하는 후보·신뢰도·취득 시각을 검증하고 지속된 의심 이벤트를 만듭니다.
기본 임계 0.8·지속 2초·허용 간격 0.5초는 실측 전 가정입니다. 단일 프레임·낮은 신뢰도는 확인 필요,
오류·오래된 관측·미래 시각·중복·소스 단절은 unknown입니다. 위험 없음으로 바꾸지 않습니다.
이 모듈 자체는 이미지를 추론하지 않습니다. 실제 모델은 아직 선정·설치하지 않았으며 실제 낙상 감지 기능은 미완료입니다.

## 모델 연결 전 필요한 사용자 결과

1. 공식 Python 카메라 초기화·읽기 결과·현재 기능 모드·호출 시간.
2. 장착 모듈의 원본 프레임 제공 방식과 해상도·fps·전원 상태. 얼굴 영상은 게시하지 않습니다.
3. Pi 수령 후 두 스트림 동시 디코딩·추론 CPU/메모리/온도/지연.
4. 모델 라이브러리와 가중치의 라이선스·배포 조건, 합성/대체물 기반 오탐·미탐·신뢰도 측정.

확인 전에는 synthetic 관측만 scenario와 연결합니다. 실물 데이터와 합성 이벤트의 source를 혼합하지 않습니다.
영상·얼굴·사진은 저장하지 않습니다. 사건에는 로봇·시각·신뢰도·임계·소스·확인 필요 상태만 남깁니다.
MQTT를 적용해도 제어 토픽에 영상을 싣지 않으며 세션·만료·신선도 검증을 유지합니다.
