# 허브 연결 끊김 정책

`host.hub.connectivity.Connectivity`는 네트워크·ROS·로봇 호출이 없는 순수 상태기계다.
부팅 시 일시 정지하며 사람이 명시적으로 재개하기 전에는 순찰 의도를 내지 않는다.
인터넷 마지막 성공 이후 기본 10초 이상이거나 로봇망이 약해지면 순찰을 일시 정지한다.
인터넷 단절은 양쪽 복귀, 로봇망 약화는 해당 로봇 복귀와 다른 로봇 정지를 의도한다.

WeakLimits의 텔레메트리 최대 나이와 손실 비율은 필수 설정이며 기본 물리 값이 없다.
테스트 숫자는 합성 조건이다. 운영자는 측정 창·샘플 수와 함께 실측한 설정을 제공해야 한다.
완전 단절·래치·위치 불신·안전 경로 없음·잘못된 관측값은 복귀 대신 제자리 정지다.
로봇 자체의 통신 두절 0.6초 래치는 그대로 유지하며 이 계층이 대신하지 않는다.

복귀는 Navigator.return_to_server 인터페이스로만 요청한다. 실제 경로 계획은 미구현이다.
Navigator가 없거나 예외·거절이면 stop 의도로 바꾼다. 요청 접수와 도착을 구별한다.
도착·실패를 다음 tick에 알려야 하며 복귀 중에도 안전 관측을 계속 갱신해야 한다.
서비스는 pause/stop 의도를 먼저 실행한 뒤 dispatch_returns를 호출해야 한다.
전체 정지는 모든 복귀보다 우선이며 실제 송신은 기존 DashboardCore가 담당한다.

연결 회복만으로 복귀를 취소하거나 순찰을 재개하지 않는다. 복귀 후에도 정지 상태다.
명시적 사람 재개와 양쪽 신선한 정상 관측·해제된 래치·안전 경로·인터넷 정상 조건이 필요하다.
실행 서비스 연결, 복귀 도착 판정과 실제 지연·손실·실물 이동은 미검증이다.
