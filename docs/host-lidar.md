# A1M8-R6 호스트 수신 기준

대상은 SLAMTEC RPLIDAR A1M8-R6 12m 제품이다. 다른 라이다의 속도나 모드를 기본값으로 쓰지 않는다.

공개 데이터시트의 측정 성능은 8000회/초 이상이며, UART는 115200bps 8N1이다.
본 구현은 **표준 스캔 5바이트 패킷**만 처리한다. 8N1에서는 바이트마다 10비트가
필요하므로 UART의 이론상 상한은 11520바이트/초, 표준 샘플만 보낸다면
2304점/초이다. 따라서 데이터시트의 8000회/초를 이 수신 경로의 전송량으로 쓰면 안 된다.
고속·압축 스캔 모드는 별도 구현 범위이다.

| 항목 | 수신·모의 서버 기준 |
| --- | --- |
| UART | 115200bps, 8 data bits, no parity, 1 stop bit |
| 통신 | 로봇의 TCP 20108 원시 양방향 중계 |
| 측정 범위 | 약 0.15~12m, 최대 거리는 흰색 대상 기준 |
| 회전 | 5V 모터에서 약 5.5Hz, 실측 전 명목값 |
| 모의 서버 | 360점/회전, 1도 간격, 약 1980점/초 |
| 모의 거리 | 합성 정사각형 방, 잡음 적용 후 150~12000mm로 제한 |

모의 서버는 20점씩 전송하며 지연 후 밀린 데이터를 몰아서 보내지 않는다.
운영체제 스케줄링과 TCP 버퍼링 때문에 수신 시점은 균일하지 않고 명목 속도보다 느릴 수 있다.
`--corrupt-every`는 정상 거리 생성과 별도로 의도적인 불량 패킷을 삽입하는 시험 옵션이다.

파서는 전송 형식의 원시 값을 보존한다. 거리 0, 낮은 품질, 150mm 미만 또는 12000mm 초과를
정상 관측으로 보장하지 않는다. 범위 밖 값을 경계 거리의 실제 장애물로 바꾸지 않는다.
ROS 어댑터와 안전 판단 계층에서 측정 무효·범위·신선도를 별도로 판정해야 한다.
파서의 각도 인코딩 정밀도 1/64도와 센서의 실제 각도 해상도 약 1도는 다른 개념이다.

명령 바이트·7바이트 디스크립터·표준 스캔 5바이트 배치는
[Slamtec 공개 SDK](https://github.com/Slamtec/rplidar_sdk/blob/master/sdk/include/sl_lidar_cmd.h)를
기준으로 확인했다. SDK 코드를 복사하거나 의존성으로 추가하지 않는다.
[공식 ROS 2 A1 실행 설정](https://github.com/Slamtec/sllidar_ros2/blob/main/launch/sllidar_a1_launch.py)의
UART 기본값도 115200bps이다. 공식 실행 설정의 스캔 모드가 이 파서의 표준 모드와
같다고 가정하지 않는다. 모의 서버는 표준 SCAN만 지원한다.

전기·측정 사양은 공개 데이터시트를 직접 확인해 요약했다. 실물 UART·회전 속도·
거리 정확도·Wi-Fi 중계 부하는 아직 검증하지 않았다.
