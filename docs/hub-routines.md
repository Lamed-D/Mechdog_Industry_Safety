# 순찰 루틴 스케줄러

`host.hub.routines.Scheduler`는 ROS·네트워크·실제 이동 없이 start_route/stop/기록 의도를 낸다.
확정 설정에서 가져온 UUID 루틴과 경로, A/B 대상, enabled, schedule을 입력한다.
시간표는 manual, daily(hour/minute/timezone=UTC), interval(seconds/anchor_utc=Z 시각)이다.
매일 시각은 현재 해당 분만 검사하며 지나간 예약을 몰아서 실행하지 않는다.
간격은 고정 anchor 기준 슬롯마다 한 번이다. 사용자가 보는 현지 시각→UTC 변환은 화면 담당이다.
서머타임 지역 시간표와 자동 로봇 교대는 아직 구현하지 않았다. 두 로봇의 개별 시간표는 지원한다.

부팅 시 held이며 명시적 사람 재개와 양쪽 준비 조건을 확인해야 예약이 시작된다.
연결·텔레메트리·배터리·래치·위치·안전 경로·지도 버전을 시작 전과 실행 중에 확인한다.
물리 임계치를 만들지 않으며 준비 판정은 기존 링크·안전 계층에서 제공한다.
사고·전체 정지·인터넷 단절은 양쪽 루틴 정지가 우선이다. 회복으로 재개하지 않는다.
이때 연결 상태기계가 서버 복귀 여부를 별도로 결정한다.
신뢰하지 못하는 시계에서는 예약 시작을 하지 않는다. 시계 역행 시 실행 중 루틴도 정지한다.
수동 시작은 이미 인증·만료 검사를 통과한 사람 명령 ID를 전달해야 한다.

예약 ID는 루틴/지도 버전/날짜 또는 간격 슬롯으로 만들고 실행 전에 reserve_run을 호출한다.
운영 연결은 Store.reserve_run을 주입한다. SQLite 고유 키로 재시작 뒤 같은 실행을 막는다.
예약 실패·디스크 오류·용량 초과는 시작을 거부한다. 실행 전 예약 후 종료된 프로세스는
같은 슬롯을 자동 재실행하지 않는다. 사람 확인과 새 수동 명령이 필요하다.
실행 중인 루틴은 completed(robot)로 완료를 알린다. done은 경로 실행기의 실제 도착 확인 뒤에만 호출한다.
활성 실행 복구·세부 지점 순서·대기 동작은 경로 실행기와 서비스의 후속 통합 대상이다.

예약과 기록은 제어 잠금 밖에서 실행한다. 실행 서비스는 pause/stop 의도를 이동보다 먼저 처리해야 한다.
원격 루틴 편집/수동 시작 봉투 확장, 실제 Navigator·시계 동기화·Supabase·Pi는 미검증이다.
