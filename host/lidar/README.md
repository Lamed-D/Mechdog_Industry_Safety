# 호스트 라이다 표준 스캔

표준 라이브러리만 사용한다. import만으로 네트워크에 연결하지 않는다.
TCP 기본 포트는 20108이며 실제 장비 연결은 사용자 확인 후 수행한다.

- `rplidar_protocol.py`: 요청, 7바이트 디스크립터, 5바이트 표준 샘플과 분할 수신 처리.
- `scan_assembler.py`: 시작 플래그 사이를 한 회전으로 묶는다. 첫 부분 회전과
  종료 시 미완성 회전은 버린다. 거리 단위는 mm, 각도 단위는 도이며 수신 순서를
  유지한다. 장착각과 방향은 생성자에서 설정한다. 거리 0은 유효한 장애물 없음이
  아니라 측정 무효를 뜻하며 품질과 함께 보존한다.
- `tcp_client.py`: STOP 후 100ms 대기, GET_HEALTH, SCAN 순서로 시작한다.
  건강 상태 0·1만 허용하고 오류·알 수 없는 상태는 스캔을 시작하지 않는다.
  `session()`은 실패를 예외로 알리고, `run()`은 실패 콜백 후 재접속한다.
  콜백에서는 `ScanAssembler.reset()` 등으로 연결 사이의 미완성 회전을 버려야 한다.
  종료 이벤트는 소켓 연결 제한시간 또는 수신 폴링 주기 후 반영된다.
  제너레이터 소비를 중단할 때는 `close()`로 STOP 전송과 소켓 닫기를 보장한다.

표준 샘플에는 체크섬이 없다. 시작/반전 비트·check 비트·각도 범위를 검사하고
한 바이트씩 이동해 동기를 회복하지만, 구조상 정상처럼 보이는 손상은 검출할 수
없다. 회전 결과는 모든 점의 무결성이나 360도 관측 완전성을 보증하지 않는다.
센서 데이터를 안전 판단에 사용하기 전 별도 신선도·품질 검증이 필요하다.

로컬 합성 서버:

```sh
python -m tools.mock.mock_lidar --noise-mm 5 --corrupt-every 31 --disconnect-after 1000
python -m unittest discover -s tests
```

서버는 기본적으로 루프백 주소에만 바인딩한다. 합성 정사각 방 데이터를 생성하며
실제 로봇을 제어하지 않는다. 모터 제어·실물 UART·ESP32 중계·Wi-Fi 부하와
물리 거리 정확도는 검증하지 않았다.

프로토콜 근거는 [공개 공식 SDK](https://github.com/Slamtec/rplidar_sdk)이며
명령·응답의 비트 배치를 확인해 독립 구현했다. 공개 SDK의 라이선스는
[BSD 2-Clause](https://github.com/Slamtec/rplidar_sdk/blob/master/LICENSE)이며
SDK 코드나 라이브러리를 복사하거나 의존성으로 포함하지 않았다.
